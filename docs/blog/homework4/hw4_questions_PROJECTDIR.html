Introduction

MaxDiff, also called Best-Worst Scaling, is a survey design for learning which items people prefer when they are forced to make trade-offs. Instead of asking a respondent to rate every class on an arbitrary 1–10 scale, each task shows a small set of classes and asks for the most-preferred and least-preferred option. That structure is useful here because people are usually more reliable at choosing a best and a worst than at deciding whether a class is a 7 or an 8 on a rating scale.

In this assignment, the items are the core MSBA classes at UCSD Rady. I estimate class preferences three ways. First, I use a simple counts analysis: the percentage of times a class is picked best minus the percentage of times it is picked worst. Second, I fit a multinomial logit (MNL) model by maximum likelihood. Third, I fit the same MNL model with a Bayesian random-walk Metropolis sampler. The three approaches should agree on the broad ordering of classes, especially at the top and bottom, while differing in how formally they model the choice process and communicate uncertainty.

Counts Analysis

The counts analysis is the simplest way to summarize MaxDiff choices. For each class, I calculate how often it was selected as best when shown and how often it was selected as worst when shown. The score is

[ _j = %_j - %_j. ]

A large positive score means the class was often chosen as the favorite and rarely chosen as the least favorite. A large negative score means the opposite. This is descriptive rather than model-based, but it is a useful first look.

# Respondent-level bootstrap confidence intervals for the counts scores.
score_for_data <- function(d) {
  sapply(labels$Item, function(j) {
    shown <- sum(d$Item == j)
    best <- sum(d$Item == j & d$Response == 1)
    worst <- sum(d$Item == j & d$Response == -1)
    best / shown - worst / shown
  })
}

From MaxDiff Data to MNL Choices

The MNL model treats the observed best and worst choices as probabilistic choices generated by latent utilities. Let (_j) be the utility for item (j). If a task shows items ({a,b,c,d}), then the probability that item (b) is picked as best is

[ P(=b) = . ]

The worst pick is modeled as a choice from the remaining items using utilities with the sign flipped. If item (c) is picked worst after item (b) has been selected best, then

[ P(=c =b) = . ]

Thus each MaxDiff task contributes two linked MNL observations: one best choice from four items and one worst choice from the remaining three. Because adding the same constant to all utilities leaves the soft-max probabilities unchanged, the model needs a normalization. I set (_1 = 0) and estimate (2,,{10}). Utilities are therefore interpreted relative to MGTA 403.

MNL via Maximum Likelihood

For each task, the likelihood contribution is the probability of the observed best pick times the probability of the observed worst pick conditional on the best pick. The log-likelihood is

[ () = _{} , ]

where (j^*_b) is the best item and (j^*_w) is the worst item.

Code 
full_beta <- function(theta) c(0, theta)

ll <- function(theta) {
  beta <- full_beta(theta)
  value <- 0
  for (i in seq_len(nrow(shown_mat))) {
    shown <- shown_mat[i, ]
    best <- best_vec[i]
    worst <- worst_vec[i]
    remaining <- shown[shown != best]
    value <- value + beta[best] - log_sum_exp(beta[shown])
    value <- value - beta[worst] - log_sum_exp(-beta[remaining])
  }
  value
}

MNL via Bayesian Estimation

For the Bayesian version, I use the same MNL likelihood with a weakly informative prior:

[ N(, 10I). ]

The posterior is proportional to likelihood times prior,

[ () L()(). ]

I sample from this posterior with a random-walk Metropolis-Hastings algorithm. The sampler starts at the MLE and proposes a normal random step for the nine estimated coefficients. The proposal step size is set to target an acceptance rate around 25–40%.

Code 
log_post <- function(theta) {
  ll(theta) + sum(dnorm(theta, mean = 0, sd = sqrt(10), log = TRUE))
}

mh <- function(beta0, n_iter = 20000, step = 0.08) {
  K <- length(beta0)
  draws <- matrix(NA_real_, nrow = n_iter, ncol = K)
  beta <- beta0
  lp <- log_post(beta)
  accept <- 0
  for (t in seq_len(n_iter)) {
    beta_star <- beta + rnorm(K, mean = 0, sd = step)
    lp_star <- log_post(beta_star)
    if (log(runif(1)) < lp_star - lp) {
      beta <- beta_star
      lp <- lp_star
      accept <- accept + 1
    }
    draws[t, ] <- beta
  }
  colnames(draws) <- paste0("beta_", 2:10)
  list(draws = draws, accept_rate = accept / n_iter)
}

Discussion

Substantively, the survey suggests that students most prefer MGTA 495 Marketing Analytics (Spring with Yavorsky), followed by MGTA 453 Business Analytics (Fall with August) and MGTA 455 Customer Analytics (Winter with Nijs). The least preferred classes by the MNL share estimates are MGTA 444 Analytics Consulting (Winter with Peterson), MGTA 451 Marketing/Finance/Operations (Summer with Wilbur/Buti/Shin), and MGTA 403 AI Math, Prog., & Analytics (Summer with Nijs). The size of the gap at the top is notable: the leading class has a much larger estimated preference share than the rest.

Methodologically, I would use the counts analysis when I need a quick and transparent summary. I would use the MLE MNL when I need a principled model-based ranking and classical standard errors. I would use the Bayesian version when I care about uncertainty in transformed outputs, such as shares of preference, or when the model might later be extended to individual-level or hierarchical preferences.

There are also caveats. The survey appears to use a self-selected sample of MSBA students, so the findings should not be generalized too far beyond this group. Preferences could also be affected by students’ current quarter, prior exposure to instructors, career goals, and the order in which options appeared. If I had more time, I would explore heterogeneity across respondents and test whether preferences differ between students with different backgrounds or career interests.

## Introduction

MaxDiff, also called Best-Worst Scaling, is a survey design for learning which items people prefer when they are forced to make trade-offs. Instead of asking a respondent to rate every class on an arbitrary 1--10 scale, each task shows a small set of classes and asks for the most-preferred and least-preferred option. That structure is useful here because people are usually more reliable at choosing a best and a worst than at deciding whether a class is a 7 or an 8 on a rating scale.

In this assignment, the items are the core MSBA classes at UCSD Rady. I estimate class preferences three ways. First, I use a simple counts analysis: the percentage of times a class is picked best minus the percentage of times it is picked worst. Second, I fit a multinomial logit (MNL) model by maximum likelihood. Third, I fit the same MNL model with a Bayesian random-walk Metropolis sampler. The three approaches should agree on the broad ordering of classes, especially at the top and bottom, while differing in how formally they model the choice process and communicate uncertainty.

## Counts Analysis

The counts analysis is the simplest way to summarize MaxDiff choices. For each class, I calculate how often it was selected as best when shown and how often it was selected as worst when shown. The score is

\[
\text{score}_j = \%\text{best}_j - \%\text{worst}_j.
\]

A large positive score means the class was often chosen as the favorite and rarely chosen as the least favorite. A large negative score means the opposite. This is descriptive rather than model-based, but it is a useful first look.

## From MaxDiff Data to MNL Choices

The MNL model treats the observed best and worst choices as probabilistic choices generated by latent utilities. Let \(\beta_j\) be the utility for item \(j\). If a task shows items \(\{a,b,c,d\}\), then the probability that item \(b\) is picked as best is

\[
P(\text{best}=b) = \frac{\exp(\beta_b)}{\exp(\beta_a)+\exp(\beta_b)+\exp(\beta_c)+\exp(\beta_d)}.
\]

The worst pick is modeled as a choice from the remaining items using utilities with the sign flipped. If item \(c\) is picked worst after item \(b\) has been selected best, then

\[
P(\text{worst}=c \mid \text{best}=b) = \frac{\exp(-\beta_c)}{\sum_{j \in \{a,c,d\}} \exp(-\beta_j)}.
\]

Thus each MaxDiff task contributes two linked MNL observations: one best choice from four items and one worst choice from the remaining three. Because adding the same constant to all utilities leaves the soft-max probabilities unchanged, the model needs a normalization. I set \(\beta_1 = 0\) and estimate \(\beta_2,\ldots,\beta_{10}\). Utilities are therefore interpreted relative to MGTA 403.

## MNL via Maximum Likelihood

For each task, the likelihood contribution is the probability of the observed best pick times the probability of the observed worst pick conditional on the best pick. The log-likelihood is

\[
\ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[\beta_{j^*_b} - \log\sum_{j \in \text{shown}}\exp(\beta_j) - \beta_{j^*_w} - \log\sum_{j \in \text{shown}\setminus\{j^*_b\}}\exp(-\beta_j)\right],
\]

where \(j^*_b\) is the best item and \(j^*_w\) is the worst item.

```{r mle-functions}
full_beta <- function(theta) c(0, theta)

ll <- function(theta) {
  beta <- full_beta(theta)
  value <- 0
  for (i in seq_len(nrow(shown_mat))) {
    shown <- shown_mat[i, ]
    best <- best_vec[i]
    worst <- worst_vec[i]
    remaining <- shown[shown != best]
    value <- value + beta[best] - log_sum_exp(beta[shown])
    value <- value - beta[worst] - log_sum_exp(-beta[remaining])
  }
  value
}
```

## MNL via Bayesian Estimation

For the Bayesian version, I use the same MNL likelihood with a weakly informative prior:

\[
\boldsymbol{\beta} \sim N(\boldsymbol{0}, 10I).
\]

The posterior is proportional to likelihood times prior,

\[
\pi(\boldsymbol{\beta}\mid \boldsymbol{y}) \propto L(\boldsymbol{\beta})\pi(\boldsymbol{\beta}).
\]

I sample from this posterior with a random-walk Metropolis-Hastings algorithm. The sampler starts at the MLE and proposes a normal random step for the nine estimated coefficients. The proposal step size is set to target an acceptance rate around 25--40%.

```{r bayes-functions}
log_post <- function(theta) {
  ll(theta) + sum(dnorm(theta, mean = 0, sd = sqrt(10), log = TRUE))
}

mh <- function(beta0, n_iter = 20000, step = 0.08) {
  K <- length(beta0)
  draws <- matrix(NA_real_, nrow = n_iter, ncol = K)
  beta <- beta0
  lp <- log_post(beta)
  accept <- 0
  for (t in seq_len(n_iter)) {
    beta_star <- beta + rnorm(K, mean = 0, sd = step)
    lp_star <- log_post(beta_star)
    if (log(runif(1)) < lp_star - lp) {
      beta <- beta_star
      lp <- lp_star
      accept <- accept + 1
    }
    draws[t, ] <- beta
  }
  colnames(draws) <- paste0("beta_", 2:10)
  list(draws = draws, accept_rate = accept / n_iter)
}
```

```{r bayes-plot, fig.height=7}
  border = NA,
  main = "Bayesian MNL posterior mean shares",
  xlab = "Share of preference"
)
segments(plot_bayes$share_lo, bp, plot_bayes$share_hi, bp, lwd = 2)
points(plot_bayes$post_share_mean, bp, pch = 16)
```

The posterior means are very close to the MLE estimates, which is expected because the prior is weak and the sample has many choice observations. The main advantage of the Bayesian fit is that uncertainty for derived quantities is easy to report. For shares of preference, I compute a share for every posterior draw and take quantiles directly. The trace plots fluctuate around a stable center after burn-in rather than drifting, which supports using the post-burn-in draws for posterior summaries.

All three methods agree strongly at the top and bottom. `r comparison$item_label[comparison$counts_rank == 1]` is ranked first by all three methods, and `r comparison$item_label[comparison$counts_rank == 10]` is ranked last by all three. The small disagreements are in the middle, especially where shares and counts scores are close. That is exactly where I would expect rankings to be unstable: a few additional choices could flip neighboring classes.

The counts method is a fast descriptive dashboard. The MLE MNL adds a formal model of the choice process and turns utilities into interpretable preference shares. The Bayesian MNL gives nearly the same point estimates here, but it makes uncertainty on shares and other derived quantities especially straightforward because every posterior draw can be transformed into a share.

## Discussion

Substantively, the survey suggests that students most prefer `r comparison$item_label[comparison$mle_rank == 1]`, followed by `r comparison$item_label[comparison$mle_rank == 2]` and `r comparison$item_label[comparison$mle_rank == 3]`. The least preferred classes by the MNL share estimates are `r comparison$item_label[comparison$mle_rank == 10]`, `r comparison$item_label[comparison$mle_rank == 9]`, and `r comparison$item_label[comparison$mle_rank == 8]`. The size of the gap at the top is notable: the leading class has a much larger estimated preference share than the rest.

Methodologically, I would use the counts analysis when I need a quick and transparent summary. I would use the MLE MNL when I need a principled model-based ranking and classical standard errors. I would use the Bayesian version when I care about uncertainty in transformed outputs, such as shares of preference, or when the model might later be extended to individual-level or hierarchical preferences.

There are also caveats. The survey appears to use a self-selected sample of MSBA students, so the findings should not be generalized too far beyond this group. Preferences could also be affected by students' current quarter, prior exposure to instructors, career goals, and the order in which options appeared. If I had more time, I would explore heterogeneity across respondents and test whether preferences differ between students with different backgrounds or career interests.
